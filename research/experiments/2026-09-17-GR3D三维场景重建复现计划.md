## 1. 本轮研究问题

如何把单目真实视频持续转换为一个可保存、可追加、跨时间保持一致的三维场景地图？

本轮只复现和扩展 GR3D 的几何入口：

```text
RGB 视频
-> 抽帧/关键帧
-> 每个时间窗口的点图与相机位姿
-> 窗口间对齐
-> 全局点云与相机轨迹
```

暂不包含：目标编号、把标注重画回原图、几何文本化、MLLM 推理与问答训练。

## 2. 需要区分的两个目标

### 目标 A：GR3D 几何阶段的可比复现

- 使用原始 Pi3。
- 对一组有限采样帧一次性预测局部点图、全局点图、置信度和相机位姿。
- 目的：确认我们能够得到与 GR3D 输入形式一致的三维几何表示。
- 边界：原始 Pi3 官方定义为尺度不变点图和仿射不变位姿，不能未经测量就声称具有可靠物理尺度。

### 目标 B：面向真实长视频的可用系统

- 使用 Pi3X、官方 `Pi3XVO` 或 VGGT-Long 的 Pi3 后端。
- 将长视频切成有重叠的窗口，用重叠帧估计 Sim(3) 变换，再进行回环优化和地图融合。
- 目的：获得可以随视频长度增长的持久三维地图。
- 边界：这属于在 GR3D 几何基线上做长序列扩展，不是 GR3D 原论文的逐项复现。

## 3. 核心假设

### H1：短片几何可复现

对 16--32 个具有足够视差、较少运动模糊的帧，Pi3 能输出视觉上连贯的点云和连续相机轨迹。

反证条件：同一静态结构出现严重重复、相机轨迹跳变，或改变输入顺序后几何显著崩溃。

### H2：重叠窗口可扩展视频长度

使用 16 帧窗口、6 帧重叠时，相邻窗口可以通过共享帧的高置信点图进行 Sim(3) 对齐，形成比单次前向更长的地图。

反证条件：窗口边界持续出现双墙、重影或尺度突变，且增加重叠帧仍不能缓解。

### H3：回环能减少长期漂移

在包含返回起点的长序列中，加入回环约束后，起点与终点的位姿/点云偏差应小于仅顺序拼接的结果。

反证条件：回环后误差不降反升，或错误回环导致全局地图变形。

### H4：动态物体需要独立处理

若直接把车辆、行人等运动区域融合进静态地图，将出现拖影、重复物体，并可能污染窗口对齐。

第一阶段的处理目标是构建静态环境地图，因此动态区域先屏蔽，不在本轮建模其三维轨迹。

## 4. 分阶段最小实验

### Phase A0：官方样例冒烟测试

- 方法：原始 Pi3，整段一次性推理。
- 数据：`third_party/Pi3/examples/skating.mp4`，默认每 10 帧采样一次。
- 输出：点云 `PLY`、相机位姿 `NPY/JSON`、采样帧清单。
- 作用：验证环境、权重、坐标系和导出链路。

### Phase A1：Pi3 与 Pi3X 同输入比较

- 固定完全相同的 16--32 帧。
- 比较点云平滑度、置信度过滤、相机轨迹和尺度稳定性。
- 原始 Pi3 是 GR3D 可比基线；Pi3X 是实用升级版，结果必须分表报告。

### Phase B：中等长度视频窗口拼接

- 方法：官方 `Pi3XVO`。
- 初始配置：`chunk_size=16`，`overlap=6`，`conf_thre=0.05`。
- 数据：100--300 个采样帧，先静态场景，再加入少量动态物体。
- 对照：无窗口拼接、仅相邻窗口拼接、注入上一窗口 pose/depth 条件。
- 重点：检查窗口边界，而不是只看整体截图。

### Phase C：长序列与回环

- 方法：VGGT-Long 管线，`Weights.model=Pi3`，开启回环检测和 Sim(3) 优化。
- 数据：KITTI/Virtual KITTI 有轨迹真值的序列，以及一段自行拍摄的闭环视频。
- 对照：关闭回环 vs 开启回环。
- 输出：分块点云、合并点云、相机轨迹、回环对、资源消耗记录。

### Phase D：动态物体消融

- 只比较两种输入：原始帧；屏蔽车辆/行人等运动区域的帧或融合掩码。
- 暂不训练新模型。
- 判断动态物体主要污染点云融合、位姿估计，还是二者都会污染。

## 6. 每次运行必须保存的输出

```text
run_dir/
  manifest.json          # 代码版本、权重、设备、参数、输入帧
  frames.txt             # 实际使用的帧和时间戳
  camera_poses.npy       # 每帧 4x4 C2W 位姿
  intrinsics.npy         # 若模型/恢复流程提供
  point_cloud.ply        # 过滤后的全局点云
  confidence_stats.json  # 置信度分布与保留点数量
  alignment_stats.json   # 各窗口 Sim(3)/SE(3) 与残差
  trajectory.png         # 相机轨迹可视化
  log.txt
```

仅生成一张 `PLY` 不算完成复现，因为无法检查尺度、轨迹、窗口错位和运行条件。

## 7. 成功标准

### 无真值数据

- 点云中的主要静态平面不出现明显双层结构。
- 相机轨迹没有非真实的瞬时跳变或尺度爆炸。
- 相邻窗口共享帧对齐后，高置信点的残差显著下降。
- 改变窗口边界后，最终结构不发生灾难性变化。
- 地图使用体素降采样后，存储规模不会随每帧像素数无界增长。

### 有真值数据

- 报告相机轨迹 ATE/RPE，不只展示点云图。
- 对已知长度报告尺度误差，区分 scale-aligned 与未对齐结果。
- 对闭环序列报告首尾位姿误差，以及回环优化前后的变化。

### 动态场景

- 运动物体区域的重影点数量或占比在屏蔽后下降。
- 屏蔽动态区域不能以严重损害静态背景完整性为代价。

## 8. 运行环境与现实限制

- 当前本机为 Apple Silicon，现有 PyTorch 不支持 CUDA，MPS 也不可用。
- 本机可完成代码准备、抽帧、结果检查和轻量后处理，不适合运行 Pi3/Pi3X/VGGT-Long 主模型。
- 第一轮建议使用 Linux + NVIDIA GPU，24 GB 显存作为较实际的起点；先用 16 帧窗口和较低分辨率验证，再扩大规模。
- VGGT-Long 会把中间点图写入磁盘；长序列实验需要单独记录峰值 GPU、RAM、磁盘占用和每百帧耗时。

## 9. 当前决定

1. 先跑 Phase A0，不立即修改 Omni-View 主代码。
2. 原始 Pi3 与 Pi3X 同时保留：前者回答“是否复现 GR3D 几何入口”，后者回答“是否适合真实长视频”。
3. 先把静态持久地图做稳，再引入动态区域屏蔽。
4. 不把 codec motion vector 当作核心重建方法；它以后最多辅助关键帧选择或运动区域发现。

## 10. 下一步唯一变量

在 GPU 服务器上固定官方 `skating.mp4` 和默认采样间隔，只改变模型版本：原始 Pi3 vs Pi3X。先确认两者都能稳定导出点云与相机位姿，再进入长视频窗口拼接。
